## 2. Signals for Azure Autoscale & Alert Rules (Cloud Week 1)

| Signal / Metric | Source in Azure | Autoscale Rule or Alert Threshold | Why It Matters |
|---|---|---|---|
| **Active Message Count (`ActiveMessageCount`)** on `redeem-requests` & `offer-events` | Azure Service Bus Metrics (Azure Monitor) | **Autoscale Rule (Worker App Service Plan / Container Apps KEDA):** Scale out +1 instance when `ActiveMessageCount > 100` for 2 min (scale in when `< 20` for 5 min). | Scales Worker consumers directly on real queue backlog rather than CPU (since I/O-bound consumers often sit at low CPU while queue lag grows). |
| **Dead-Letter Message Count (`DeadLetterMessageCount`)** per queue/subscription | Azure Service Bus Metrics | **Sev-2 Alert:** `DeadLetterMessageCount > 0` over 5 min window -> trigger Ops runbook (`DlqTool peek` / `resubmit-all`). | Any message in the DLQ means all transient retries (`MaxDeliveryCount = 3`) were exhausted or a permanent contract error occurred. |
| **Outbox Unsent Backlog, Lag p95 & Poison Count (`RetryCount >= MaxAttempts`)** | Custom OpenTelemetry Meter / Log Analytics (`OutboxPoisonMessage` `LogCritical`) + SQL query | **Sev-1 Alert:** `OutboxPoisonMessage` count `> 0` OR `unsent_count > 500` for 5 min. | If `OutboxDispatcher` is stalled or a destination is misconfigured, the API still returns `202 Accepted` while downstream processing silently stops. |
| **Stuck Transactions (`RedeemTransactions` in `Pending`/`Processing` > 60s)** | Log Analytics alert on `RedeemReconciler` warning (`Reconciled stale RedeemTransaction`) | **Sev-2 Alert:** Any reconciled stale transaction (`count > 0` in 5 min). | Proves end-to-end SLA breach between `202 Accepted` and final state transition. |
| **HTTP `5xx` Rate (`503 Service Unavailable`), Circuit Breaker State & Latency `p95`** | Application Insights (`requests`, `dependencies`, Polly resilience telemetry) | **Sev-1 Alert:** `5xx rate > 1%` or `BrokenCircuitException > 0` for 2 min; **Autoscale API:** CPU `> 70%` or HTTP queue length `> 50`. | Detects dependency outages (Ollama/OpenAI, SQL, downstream APIs) the instant the circuit breaker trips. |
| **SQL Connection Pool & DTU / vCore Utilization** | Azure SQL Metrics + `dotnet-counters` (`Microsoft.Data.SqlClient`) | **Warning Alert:** SQL CPU/DTU `> 80%` or active connections approaching `MaxInstanceCount * MaxConcurrentCalls`. | Ensures scaling out Workers (`N instances × MaxConcurrentCalls`) never exceeds Azure SQL max concurrent logins/sessions. |
